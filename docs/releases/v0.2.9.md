# MP14Tools 0.2.9

为 Xiaomi Book Pro 14 2026 定制的单进程小工具：重映射触摸板重按与厂商（OEM）热键，
调节按压阈值与震动力度，并在电池供电时按设定档位调整刷新率、检查内屏 HDR。

**下载**：`mp14tools.exe` — 单文件，免安装，无需管理员权限，Windows 10 1809+ / 11 (x64)。
内嵌版本 `FileVersion` / `ProductVersion` = `0.2.9.0`；产物大小、SHA256 与 FileVersion 由发布工作流
在构建后追加到本页末尾，取自实际要上传的那个文件。

## 本版变化

> 上一个正式发布是 0.2.5，下面按功能列出 0.2.5 → 0.2.9 的全部用户可见改动。

### 通知窗口

- 每个通知都多了一个**常驻的「忽略」按钮**，不必再等超时才能关掉。
- 窗口改为**略半透明**（它是浮层，不是对话框），文字与按钮居中。
- **5 秒无操作后 1 秒淡出收起**，不再占着屏幕等 25 秒。

### OSD 提示条

- 停留时长可调（默认 5 秒），之后**1 秒淡出**（此前为 2 秒）。
- 仍然不抢焦点、不挡点击。

### 显示调节

- 电池供电时把刷新率切到设定档位：**内屏 60 / 120 Hz**，**外屏最高档 / 60 Hz**；行为可选
  不处理 / 通知确认 / 直接切换。
- **切换前的档位现在写入 `display_state.json`**：重启之后插回电源依然能恢复到原来的档位
  （此前只存在内存里，重启就丢）。
- **程序启动时按当前电源状态先执行一次策略**，不会再出现"开机时已经是电池档位、程序却一直不动"的情况。
- 报告不出电池状态的机器（台式机、部分虚拟机）**直接跳过**，不会去猜一个档位来改你的屏幕。
- 显示档位改由**面板自己上报的能力**推导，移除了对可选 SRR 文件夹 `config.json` 的依赖。
- HDR 只针对内屏；切电源、切刷新率以及电池模式下每次唤醒都会检查一次。

### 日志

- 电池下"无需调整"时会把**实际比较过的档位**写进日志；插回电源时也会记录有没有档位需要恢复，
  这样"策略没跑"和"跑了但不用动"一眼能分清。

# MP14Tools 0.2.9 (English)

Single-file `mp14tools.exe` — no installer, no admin rights, Windows 10 1809+ / 11 (x64).
Nothing to install: run the exe, the settings window opens, closing it keeps the tool in the tray.
The embedded `FileVersion` / `ProductVersion` is `0.2.9.0`; the size, the SHA256 and the FileVersion of
the shipped binary are appended to the end of this page by the release workflow.

## Changes since the last release (0.2.5 → 0.2.9)

- **Notice window**: every notice now carries a permanent **"ignore" button**, the window is slightly
  translucent, and it **fades out over 1 second after 5 seconds** without an answer (it used to sit
  there for 25 seconds).
- **OSD**: the hint bar still holds for the configured time (5 s by default) and now **fades out over
  1 second** instead of 2.
- **Display policy**: the mode from before a switch is **written to `display_state.json`**, so plugging
  the charger back in restores it even after a restart; the policy is also **evaluated once right after
  start-up**; machines that cannot report a battery state (desktops, some VMs) are **skipped** instead
  of guessing; the available modes are derived from what the panel reports itself (no SRR folder import).
- **Logs**: "nothing to do" now names the rates that were compared, and a restore logs whether there was
  anything to restore.

## Verification

- Release build with the GNU toolchain (rustc 1.98.1) via `.\build.ps1 -Release`: exit 0, no warnings.
- Smoke run: settings window / tray icon / touchpad raw input / start-up display check all come up.
- The release is rebuilt from the tag by `.github/workflows/release.yml`, which refuses to publish when
  the manifest version, the tag and the embedded `FileVersion` do not all agree.
